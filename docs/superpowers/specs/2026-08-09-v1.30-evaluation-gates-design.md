# v1.30 Evaluation Gates Design

## Status

Accepted on 2026-08-09 after an eighteen-question product review. This release
is evaluation-first: it may ship no retrieval or linking behavior change when
the evidence does not justify one.

## Goal

Turn the project's known semantic limits into reproducible release gates before
adding embedding, query expansion, or a new relatedness score. Preserve the
existing explicit-write, local-first, deterministic, and bounded-cost product
boundaries.

## Data Boundary

The private reference Vault may be inspected read-only to discover realistic
failure shapes. Repository fixtures contain only synthetic or minimized
material, labels, and aggregate metrics. They must not contain private note
bodies, personal paths, project names, signed URLs, credentials, or copied
conversation text.

## Phase 1: Web Capture

The first gate contains twelve cases: four standard captures, four verified
captures, and four zero-write failures. The reference Agent is Codex; other
platforms retain installation, doctor, manifest, and helper smoke coverage.

Each case runs three times with the same Skill revision, model identity, prompt,
and source snapshot. One hard failure fails the case:

- invented source access, claim, number, quotation, or citation;
- an author self-report or inference presented as verified fact;
- completion claimed while material source content is unavailable;
- a Vault write in a zero-write case;
- a verified note whose receipt does not bind the final candidate.

Soft scoring starts only after the hard gate and records required-fact coverage,
structure, source/inference labeling, and the worst as well as mean result. If a
hard failure appears, later retrieval and link work stops until the Web Capture
case passes all three repeats.

## Phase 2: Retrieval

The baseline contains forty queries: ten exact, eight alias or bilingual, eight
metadata-filtered, eight semantic paraphrases, and six true no-answer cases.
Each query declares a set of acceptable notes rather than one brittle filename.
Metrics are Recall@5, MRR, no-answer false-positive rate, and latency.

A future enhancement is admissible only when it:

- adds valid hits for at least two of eight semantic queries;
- causes no Recall@5 regression in exact, alias, or filtered queries;
- adds no no-answer false positive;
- preserves citations, lines, filter diagnostics, and read-only behavior;
- keeps P95 latency at no more than twice the lexical baseline;
- remains offline and requires no persistent index or resident service by
  default.

Candidate order is deterministic query expansion from aliases and the Vault tag
vocabulary, then explainable bilingual terminology, then bounded graph/title
expansion, and only then optional disabled-by-default local embedding.

## Phase 3: Directed Links

v1.30 builds an evaluation set but no new scorer. Positive examples must answer:
"Following A to B, what does the reader learn about A?" Each positive records
directional evidence. Hard negatives deliberately share a topic while adding
nothing about the source note. Similarity alone is not a relation.

## Explicit Deferrals

- no automatic link insertion;
- no embedding implementation without a measured baseline win;
- no automatic migration of customized templates or historical Digests;
- no Cursor-specific compatibility layer or session hot-reload work;
- no semantic claim that mechanical audit findings can prove factual truth.

## Release Evidence

The release report records fixture composition, all reference-Agent repeats,
hard failures, soft scores, retrieval metrics, directed-link labels, real-Vault
read-only digest equality, full pytest, generated-tree parity, lockfile status,
installed wheel smoke tests, pre-PR review rounds, and GitHub Actions results.
