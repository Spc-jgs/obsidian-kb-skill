# Obsidian 笔记写后治理增强设计

## 背景

v1.4.0 已实现 Folder Index、中文模板、受限 Wikilink 搜索和 Vault 审计，但一次真实的 QoderWork 执行暴露了两类缺口：

- 写入前完成了 Vault 验证，写入后没有验证新笔记，导致 6 个标签和非小写标签进入远端。
- Git 冲突解决把 Java 的插件索引改回手工笔记列表，破坏了 Folder Index 的唯一索引所有权。

本次改动强化现有工作流，不引入后台服务、状态数据库或自动全库扫描。

## 目标

1. 每次创建或更新笔记后，在确认、提交或推送前完成确定性的写后验收。
2. 审计器能发现 Folder Index 索引缺少或重复 `folder-index-content` 块。
3. 明确 Vault 本地治理文件优先于 Skill 的通用默认规则。
4. 消除“每次只写一篇”与“多主题拆分”之间的规则矛盾。
5. 让成本预算准确反映内容读取成本，不因短小控制文件产生假性超限。
6. 提供受本地规则控制的安全 Git 后处理，不默认扩大外部写入范围。
7. 修复当前知识库已经出现的索引与标签违规。

## 方案比较

### 方案 A：只修改文档措辞

优点是改动小。缺点是无法自动发现缺失的 Folder Index 内容块，也不能防止未来再次提交错误索引。

### 方案 B：文档规则与审计器同时增强（采用）

在 `core/OBSIDIAN_KB.md` 中补齐写后验收、规则优先级、成本和 Git 边界；在现有 `audit_vault.py` 中增加 Folder Index 结构检查，并用测试锁定行为。该方案复用现有架构，能够同时约束 Agent 行为和检测最终文件状态。

### 方案 C：增加独立 Vault 配置清单和自动 Git 编排器

可以把插件配置、Git 策略和路由集中到新配置文件，但会引入配置同步问题和额外维护负担。当前规模下不采用。

## 详细设计

### 1. Vault 本地规则优先级

Skill 明确采用以下优先级：

1. 用户当前请求；
2. Vault 内适用于目标文件的 `AGENTS.md`、`CLAUDE.md` 或其他本地治理文件；
3. Skill 的通用规则和路由表。

通用路由只作为 fallback。执行写入前应读取适用的本地治理文件，但不得借此扩大为全库扫描。

### 2. Folder Index 配置读取

保留对 `.obsidian/plugins/obsidian-folder-index/data.json` 的读取，因为 `graphOverwrite`、索引文件命名和新目录初始化规则无法从单个 INDEX 文件可靠推断。

插件清单、插件配置、模板和治理文件属于控制面文件；它们仍计入“扫描文件总数”，但不占“内容笔记全文读取”额度。

### 3. 写后验收

在创建和更新工作流中增加“Validate Result”步骤，位于写文件之后、用户确认及任何 Git 操作之前。至少检查：

- 文件位于预期目录，文件名和编码符合规范；
- YAML 可解析，必填字段存在；
- `type` 合法；
- 标签为全小写 kebab-case 且不超过 5 个；
- 没有遗留 `{{date}}` 等模板占位符；
- Wikilink 数量未超限且没有为了配额制造弱链接；
- Folder Index 或 Dataview 模式下没有手工追加目录成员；
- 新目录的插件索引包含一个 `folder-index-content` 块。

如果仓库提供 `scripts/audit_vault.py` 或等价审计命令，优先运行；否则执行上述目标文件级检查。验收失败时先修正，再进入确认或 Git 阶段。

### 4. Folder Index 审计规则

审计器对所有 `type: folder-index` 的 Markdown 文件检查 fenced code block：

- 0 个：报告 `missing-folder-index-content`；
- 1 个：通过；
- 大于 1 个：报告 `duplicate-folder-index-content`。

该规则只检查插件结构，不禁止 INDEX 中的人工说明、学习进度或跨目录导航。

### 5. Web Clip 的“理解”标准

模板标题调整为“理解与启发”。内容要求为 2–4 句或等量短列表：

- 基于原文事实进行归纳；
- 明确区分原文观点和 Agent 推论；
- 不冒充用户表达个人偏好；
- 不机械复述“核心观点”。

### 6. 多主题处理

默认一次调用只创建或更新一篇目标笔记。来源中包含多个解决方案，不等于存在多个独立主题。

只有当内容确实包含多个可独立复用的知识主题时，Agent 才建议拆分；如果拆分会超过一篇笔记的硬限制，必须先获得用户确认。未确认时创建一篇聚合笔记，并把后续拆分作为建议，不自动扩大写入范围。

### 7. Wikilink 搜索

保持 bounded search，不增加全库全文搜索。候选目录按以下顺序选择：

1. Vault 本地路由规则；
2. 目标目录 INDEX 中的人工导航；
3. 父目录 INDEX 中的主题说明；
4. 最多 1–2 个高相关兄弟目录。

没有高置信度结果时允许 `related: []` 和空的关联笔记章节。

### 8. 安全 Git 后处理

Git 不是通用默认动作。只有用户明确要求，或 Vault 本地治理文件明确要求时才执行。

执行时必须：

1. 写后验收通过；
2. 检查工作区并只暂存本次任务产生的文件；
3. 不提交或覆盖无关本地改动；
4. push 前 fetch 并检查本地与远端是否分叉；
5. 如果发生分叉、冲突或需要修改非本次文件，停止并报告，不自动选择冲突一侧；
6. 不得通过恢复手工目录列表来解决 Folder Index 冲突。

### 9. 当前知识库修复

- 恢复 `20-Learning/Java/INDEX.md` 的唯一 `folder-index-content` 块，保留人工目录说明，删除手工成员列表。
- 将 OrbStack 笔记标签缩减为最多 5 个，并改为全小写 kebab-case。
- 用增强后的审计器验证远端最新知识库快照。

## 测试策略

### 自动化测试

- 先增加缺失 Folder Index 内容块的失败测试。
- 再增加重复内容块的失败测试。
- 保留现有合法索引通过测试，避免误伤人工说明。
- 运行完整 `pytest`。
- 运行 `python build.py --check`，确保四个平台适配器与 core 同步。

### Skill 文档场景验证

通过固定场景检查生成适配器均包含：

- 本地规则优先级；
- 写后验收；
- 单笔记默认边界；
- 安全 Git 分叉处理；
- “理解与启发”产出标准。

### 知识库验收

- 对修复后的 Vault 运行严格审计，结果必须为 0 findings。
- 检查 Java INDEX 恰有一个 `folder-index-content` 块。
- 检查 OrbStack 笔记标签不超过 5 个且全部规范。
- 确认 `.obsidian/workspace.json` 未被修改。

## 非目标

- 不增加全库语义搜索或向量数据库。
- 不自动把一篇来源拆成多篇笔记。
- 不默认 commit 或 push 任意 Vault。
- 不自动解决 Git 内容冲突。
- 不删除 INDEX 中合法的人工说明、学习进度或跨目录导航。
